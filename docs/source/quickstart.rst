Quickstart
==========

This guide introduces the basic py4radiation workflow for
generating radiative heating, cooling and ion fractionn tables
from custom spectral energy distributions (SEDs).

The examples use a continuous star-formation model from
Starburst99, but the same workflow can be applied to other
supported SEDs.


1. Preparing a radiation field
------------------------------

The :class:`~py4radiation.radiation.sed.SED` class prepares
the input SED into Cloudy-readable format.

For example, consider a stellar population with:

* Continuous star formation.
* Star-formation rate of 5 solar masses per year.
* Stellar population age of 3 Myr.
* Distance of 1 kpc from the source.

The corresponding SED can be prepared using:

.. code-block:: python

   from py4radiation import SED

   sed = SED(
       run_name="example",
       table_id="8b",
       sfr_msun_yr=5.0,
       distance_kpc=1.0,
       age_myr=3,
   )

   sed_path = sed.write_outfile()

   print(sed_path)

The generated Cloudy input file is:

.. code-block:: text

   example_z0.0000e+00.out

The file contains the interpolated spectral shape and the
absolute normalisation at 1 Ryd.


Starburst99 normalisation
~~~~~~~~~~~~~~~~~~~~~~~~~

Starburst99 Figures 7-12 contain stellar-only spectra,
without the nebular continuum included in Figures 1-6.

The luminosity of continuous star-formation models (Figures 8, 10 and 12) scales with the star-formation rate.
For instantaneous-burst models (Figures 7, 9 and 11), the luminosity scales with the initial stellar mass.

The spectral flux density is calculated as

.. math::

   F_\nu = \frac{L_\nu}{4\pi d^2},

where :math:`L_\nu` is the spectral luminosity and
:math:`d` is the distance from the source.


2. Generate Cloudy parameter files
----------------------------------

The :class:`~py4radiation.radiation.parfiles.ParameterFiles`
class generates the parameter files required by pyCIAO.

The following example creates a small density-temperature
grid for demonstration purposes:

.. code-block:: python

   from py4radiation import ParameterFiles

   par = ParameterFiles(
       cloudy_path="/path/to/cloudy.exe",
       run_name="example",
       elements="H C N O",
       n_limits=(-9, 4),
       n_spacing=0.125,
       T_limits=(1, 9),
       T_points=321,
   )

   hc_parfile = par.hc_parfile()
   ib_parfile = par.ib_parfile()

   print(hc_parfile)
   print(ib_parfile)

The generated parameter files are:

.. code-block:: text

   example_hc.par
   example_ib.par

The first file configures heating and cooling calculations,
while the second configures ionisation-fraction calculations.

Both reference the radiation-field file generated in the
previous step.

.. note::

   Replace ``/path/to/cloudy.exe`` with the actual path
   to your Cloudy executable.

   Generate the SED and parameter files from the same
   working directory so that the generated radiation-field
   path is correctly referenced.


3. Execute Cloudy with pyCIAO
-----------------------------

pyCIAO provides a command-line interface for executing
Cloudy calculations.

Heating and cooling calculations can be started with:

.. code-block:: bash

   pyciao example_hc.par --nproc 4

Ionisation-fraction calculations can be started with:

.. code-block:: bash

   pyciao example_ib.par --nproc 4

The ``--nproc`` argument specifies the number of Python
multiprocessing workers.

Each worker executes a subset of the Cloudy calculations
defined by the parameter file.

The generated outputs are stored in the corresponding
subdirectories:

.. code-block:: text

   hc/
   ib/

Each directory contains a master ``.run`` file and
the numerical maps generated by Cloudy.

The master ``.run`` file records the parameter combinations
associated with the numbered calculations.


MPI execution
~~~~~~~~~~~~~

If py4radiation was installed with MPI support and a
compatible MPI environment is available, calculations
can also be distributed across MPI ranks.

For example:

.. code-block:: bash

   mpiexec -n 4 pyciao example_hc.par

When multiple MPI ranks are detected, pyCIAO uses MPI
instead of Python multiprocessing.

.. note::

   The examples in this section execute external Cloudy
   calculations. You need a working Cloudy installation and
   valid parameter files.


4. Process heating and cooling tables
-------------------------------------

The :class:`~py4radiation.utils.hc_tables.HeatingCoolingTables`
class combines the individual heating/cooling maps into a single table.

.. code-block:: python

   from py4radiation import HeatingCoolingTables

   hc = HeatingCoolingTables(
       run_dir="hc",
       run_name="example",
   )

   table_path = hc.write_table()

   print(table_path)

This generates:

.. code-block:: text

   example_cooltable.dat

The default table contains:

* Hydrogen number density in cm^-3.
* Temperature in K.
* Heating coefficient.
* Cooling coefficient.
* Mean molecular weight in atomic mass units.

By default, the heating and cooling rates are normalised
by the square of the hydrogen number density.

The resulting coefficients have units of
erg cm^3 s^-1 for this normalisation.


5. Process ionisation-fraction tables
-------------------------------------

The :class:`~py4radiation.utils.ib_tables.IonTables` class
combines the individual ion fraction maps into an HDF5 file.

.. code-block:: python

   from py4radiation import IonTables

   ib = IonTables(
       run_dir="ib",
       run_name="example",
       elements="H C O",
   )

   ib.write_table()

This generates:

.. code-block:: text

   ib/example_iontable.h5

The HDF5 file contains logarithmic ionisation fractions
for the selected chemical elements.

The dataset dimensions are ordered as:

.. code-block:: text

   (ionisation stage, density, redshift, temperature)

For calculations performed only at z=0, the data are
duplicated at z=1e-4 to provide the redshift dimension
required for Trident interpolation. This is not intended
to show cosmological evolution, but a way to match with
the expected table dimensions.

This additional redshift slice does not represent a
separate Cloudy calculation.


6. Alternative radiation fields
-------------------------------

The same workflow can be applied to other radiation
sources supported by py4radiation.


Haardt & Madau (2012) background
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

To generate the metagalactic ultraviolet background
at z=0:

.. code-block:: python

   from py4radiation import SED

   sed = SED(
       run_name="hm12_example",
       table_id="HM12",
   )

   sed.write_outfile()

The original HM2012 tables provide the specific intensity :math:`J_\nu`.

py4radiation converts this quantity into

.. math::

   F_{\nu,\mathrm{equiv}} = 4\pi J_\nu,

in erg s^-1 cm^-2 Hz^-1.

Unlike stellar radiation fields, HM2012 does not require
distance, star-formation-rate or stellar-mass scaling.

A local HM2012 table can also be supplied through the
``hm12_path`` argument.


Custom spectral energy distributions
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Users can provide their own spectral luminosity tables.

The input must contain two columns:

* Wavelength in Angstroms.
* :math:`\log_{10}(L_\lambda)`, with :math:`L_\lambda`
  in erg s^-1 Angstrom^-1.

For example:

.. code-block:: python

   sed = SED(
       run_name="custom_example",
       table="custom_sed.dat",
       distance_kpc=1.0,
   )

   sed.write_outfile()

The custom luminosity spectrum is converted to spectral
flux density using the specified distance.
